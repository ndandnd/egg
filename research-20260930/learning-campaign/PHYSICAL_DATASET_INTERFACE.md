# Completed physical-label shard adapter

This first-attempt adapter requires exactly one wrapper receipt. A deliberately resumed attempt with multiple job receipts needs an explicit later admission policy that accounts for every allocation; this version excludes it rather than silently combining runs.

`PYTHONPATH=src python3 -m experiments.physical_learning_dataset --attempt result/physical_learning/20260930-shard00-attempt1 --output result/physical_learning/dataset-train-shard00-v1` accepts only explicit completed **training** shard paths. Repeat `--attempt` to pool distinct shards. The output directory must not exist. This adapter performs pure replay and validation; it launches no solver and fits no model. A partial shard is **excluded** with an error, not converted to an all-zero or incomplete training record. The raw attempt remains archived with its failures and paid time.

Admission requires the versioned generator, exactly eight unique declared training base IDs, the exact 64-cell manifest order, catalog rows and corresponding matching per-cell receipts, a completed 64-cell summary, exactly one matching successful Slurm wrapper receipt with freeze/preflight/controller/overall return codes zero, and frozen manifest/source hashes. It checks case and market identities against the explicit train generator, not against development or sealed-test material. Every feasible source or charged plan is independently replayed. A charged plan must match its source plan hash and exact movement set; its fixed-charge evidence, direct target rescore when present, native status, and exact curved bill must agree. A source-market lower certificate stays tagged as **source-market** metadata, never a target-price lower bound. Failed/time-limited cells may still contain a physically replayed feasible plan, but all such plans remain provisional for the reported curved objective. The fixed-route LP optimizes a linear tariff; it does not certify curved or global optimality.

The immutable dataset has `cases.jsonl` (one serialized physical graph/assumption set per independent base group), `source_inputs.jsonl` (replayed full source plans available before target charging), `source_outcomes.jsonl` (source solver status, bounds, receipts, time), `target_inputs.jsonl` (declared target market, source topology/hash and exact **direct** target bill), `target_outcomes.jsonl` (replayed charged plan, exact post-charge bill, failure/censoring/status/time), `health.json`, and `dataset_receipt.json`. Each target input and outcome shares a stable cell key; no target outcome appears in an input file. The receipt pins every ingested manifest/frozen/catalog/summary/cell/evidence hash, the original execution source hashes, and this adapter/CLI/interface source hashes.

`target_inputs.direct_exact` is computable from an acquired source plan **before** charging and is valid for a direct-rescore baseline; it is not the post-charge target label. Identity fields such as `base_id`, `base_group`, `case.name`, `physical_profile.base_id/split`, `source_plan.case_identity`, hashes, and receipt paths are join/provenance data, not numeric predictive features. The containers hold raw graph and plan structure for later route learning; this adapter does **not** create an ML feature matrix or enforce a numeric feature whitelist. A future trainer must specify and test an explicit numeric projection using training-only preprocessing and excluding IDs, solver outcomes, bounds, statuses, failures, and paid time. Whole base groups, not two sources or three tariff variants, are the independent units for grouped CV.

`health.json` reports every intended/replayed/censored label, native-limit outcomes, wrapper and native statuses, source-pair topology/full-plan equality with denominators, winner counts and descriptive entropy, exact margins and ties at fixed tolerance `1e-6`, complete replayed pairs, exclusions, and breakdowns by battery regime and case size. A physically replayed label has separate `curved_optimality_uncertified`, `provisional_after_native_limit`, and `feasible_after_child_failure` flags; an LP native `OPTIMAL` status applies only to its linear subproblem and never proves minimum curved or global fleet cost. Winner labels compare only the two observed paid charging outcomes. Missing or nonreplayed outcomes remain `null` and are explicitly excluded from paired supervised targets. The next model-fit protocol must decide whether and how to use provisional physically feasible labels; this adapter makes that state visible without silently promoting them to certified values.
