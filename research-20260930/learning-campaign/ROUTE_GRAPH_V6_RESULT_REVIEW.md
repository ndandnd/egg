# Graph v6 result review

**Verdict:** No material blocker found. The results report and replay JSON agree on the measured outcomes and keep the graph study within its stated edge-imitation scope.

The final replay passed 313,950 checks with no failures across all 12 tasks and both selected arms (24 fitted arm instances). It checks saved task/result/source identities, every progress-file hash, the exact frozen source set against both the submission commit and current checkout, fit-only transforms and group partitions, candidate selection, inner promotion, and saved fit/inner/outer outputs. Each task’s five native runtime probes passed before its bank-launch marker. The probe logs identify the same `unicorn-cpu-75` CPU; the task launches use the pinned Linux Torch/NumPy/SciPy/scikit-learn/joblib versions.

The initial replay’s three failures were accounting-only: it treated batch and extern step rows as parent task rows. The failed JSON and script are retained. The corrected accounting associates 24 step rows with the exact 12 parent IDs, node and start time, then sums parent allocations only. It confirms 12 completed tasks, 10,335 elapsed and allocated CPU-seconds, a maximum batch RSS of 543,344 KiB (about 531 MiB), and at most four concurrent tasks. The 36 archive files cover all 12,770 collected files exactly once; manifest totals match 1,348,963,777 raw bytes and 805,271,829 archive bytes. The log receipt covers all 24 stdout/stderr logs.

The numerical qualification is clear and appropriately limited. The verifier uses a frozen absolute tolerance of 1e-10 and reports maximum differences of 2.66e-15 for probabilities, 1.71e-14 for metrics, 2.78e-17 for stable BCE, and zero for the fit transform. It runs a functional float64 CPU replay on macOS ARM against saved Linux x86-64 Torch outputs, so this supports close numeric reproduction, not bitwise identity or a fully matching runtime. The report states that distinction and notes the different local sklearn/joblib versions.

The aggregate table and paired-policy text match the JSON. For full128, graph inner promotion has log loss 0.0718878, AP 0.8425725 and top-k recall 0.7395697; v5 tree inner promotion has 0.0701272, 0.8262564 and 0.6939243. That is +0.0017606 log loss, +0.0163162 AP and +0.0456455 top-k recall (4.56 percentage points). The common32 values also match. Attention was selected in 11 of 12 fold/seed tasks and mean pooling in one.

All 24 arm fits reached the 300-epoch cap; the selected epochs were 298–300 for mean pooling and 297–300 for attention. The report treats this as a reason to define a separate budget study, not evidence that more training would improve held-out results. Its other scope limits are sound: 128 repeated TRAIN timetables are exploratory, edge labels mark membership in observed feasible incumbents, top-k is a ranking diagnostic, and no fleet-feasibility, cost or online-speedup result follows. The graph’s inherited 17 edge features also leave battery/SOC and charger context for a separately versioned study.

One nonblocking presentation option: the main table compares the v6 inner-promoted policy to the v5 inner-promoted policy, while the individual v5 CatBoost and XGBoost scores appear in the replay JSON rather than the table. The policy comparison is the appropriate primary comparison; showing the strongest individual v5 tree row would make the “strongest tree baselines” statement self-contained.
