# Exact-128 TRAIN scorer budget extension: saved-model replay

The longer MLP optimization budget improved the predeclared, equal-timetable held-out movement-classification metrics on both the full 128-group cohort and the matched original 32-group cohort. The extended HistGBDT iteration menu did **not** show the same consistent result: full-128 average precision and trip-count top-k recall rose slightly while log loss worsened, and all three measures worsened on common 32. These are observed feasible source-incumbent edge labels, not optimal-route truth; no complete-fleet feasibility, curved operating-cost, or production route benefit follows from this scorer comparison.

|---|---:|---:|---:|
| MLP32, full 128 | 0.091523 → **0.084204** | 0.730048 → **0.747740** | 0.659818 → **0.673704** |
| MLP32, common 32 | 0.091571 → **0.084321** | 0.722634 → **0.740108** | 0.664997 → **0.677241** |

| HistGBDT, common 32 | **0.069285** → 0.070361 | **0.832559** → 0.828967 | **0.700663** → 0.697574 |

The v4-minus-v3 MLP changes on the same 128 timetables are −0.007319 log loss, +0.017692 average precision, and +0.013886 top-k recall. On the same original 32 timetables they are −0.007250, +0.017474, and +0.012245. The corresponding tree changes are +0.000479, +0.000901, +0.005274 on full 128, and +0.001077, −0.003592, −0.003089 on common 32. These are descriptive paired differences after averaging the three fixed seeds and observed source fleets within each timetable; model variants and seeds are not additional independent timetables.

The strict [read-only replay](replay_route_model128_budget_v4.py) verified all 12 completed task, wrapper, source and append-only inner-progress receipts; identical v3/v4 split membership, feature/weight manifests, fit-only preprocessing and shared source hashes; every v4 selected saved outer probability and per-source/group/pooled metric; and the fixed original-32 subgroup. The [verification JSON](ROUTE_MODEL128_BUDGET_V4_REPLAY.json) has the per-task checks, exact selected metrics, per-group seed/source averages and full-128/common-32 paired distributions. It covers 128 registered TRAIN timetables and 255 actually replayed source fleets; base 10037 retains its one censored source, with no imputation. No model was refit and no development or sealed-test case was opened.

All 12 v4 MLP runs reached the old 300-epoch anchor. Their saved 300-epoch parameters and every shared fit/inner checkpoint matched frozen v3, as did the independent 200-tree candidate's fit, inner and outer predictions. The MLP selected epoch ranged from 730 to 1200 (mean 1017); nine tasks stopped early under the frozen inner patience and three reached the 1200 cap. The tree selected 200, 400 and 800 iterations in 3, 3 and 6 tasks respectively, using inner log loss only. The extended tree selected models had an average inner-minus-fit log-loss gap of 0.01286, compared with 0.00409 at the 200-tree anchor, which is consistent with increasing fit/inner separation and helps explain the mixed outer result. This is a diagnostic, not an outer-based checkpoint choice.

One control has independent-run drift despite identical logistic configuration, splits, weights, fit-only preprocessing, pinned library versions and all ten shared source hashes. Nine of 12 v3/v4 logistic tasks have different `lbfgs` iteration counts; the largest coefficient difference is 0.0190 and largest saved outer probability difference is 0.0000975. Within each v4 run, logistic predictions and metrics strictly replay from its saved coefficients; the largest per-task outer log-loss difference versus v3 is 0.00000142 and average-precision difference is 0.000180. These small differences should not be credited to the MLP/tree budget change. A fit-only kind-rate rounding tie also changed a control ranking if recomputed on the local CPU; the verifier uses each task's persisted fit-only rates to reproduce its saved predictions exactly. The frozen 300/200 model anchors remain strictly matched, separate from these control diagnostics.
