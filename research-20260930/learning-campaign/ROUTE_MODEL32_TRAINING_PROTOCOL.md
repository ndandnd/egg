# Pooled 32-group physical source-route scorer, version 2

This prospective CPU experiment pools exactly TRAIN base IDs `10000–10031`: admitted shard 0 composite plus completed/admitted shards 1–3. The pool CLI checks each saved dataset receipt and case/source table hash, then writes an immutable `result/physical_learning/20260930-route-pool32-v1` containing only case and source-fleet inputs plus a versioned manifest of all admission hashes. It performs **no new native replay or optimization**; the upstream adapters already replayed physical evidence. No development, reserved test, target charging outcome, objective value, native status, or bound enters the scorer's feature matrix. The pool-manifest SHA-256 is passed explicitly to every training worker and pinned in every launch/result/receipt.

The label for each candidate movement is whether it appears in one observed feasible source fleet. Unselected movements are not known to be infeasible or inferior, and source incumbents may have open solver gaps. The 17 explicit numeric features are the existing case/source-price `learned_proposals.FEATURES` (movement kind, scaled times/energy/charging window, source tariff summaries, same-place, intercept). IDs and source hashes are join and audit keys only. Source variants stay with their timetable in all splits. This experiment measures held-out **edge prediction**, not physical feasibility, route quality, target-cost savings, or solver speed.

Four outer timetable folds each hold eight independent groups. Within the other 24 groups, a fixed index rule reserves four entire timetables for inner validation and fits on 20. The three seeds are 17, 29 and 43, yielding 12 immutable tasks. For every model, normalization, prevalence, kind frequencies and sample weights are learned from the 20 fit groups only. There is no refit on the inner four for this version. The outer eight are touched only after all stopping and configuration choices are fixed. Both variants of any case remain in the same fit, inner, or outer partition. Each observed full fleet has equal weight, then movements within it have equal weight.

Controls are constant fit prevalence and fit-only movement-kind frequency. A regularized scikit-learn logistic regression uses `lbfgs`, fixed `C=1`, `tol=1e-6`, and `max_iter=1000`; the recorded `n_iter` and convergence warning establish whether it actually converged. A 32-hidden-unit tanh MLP uses full-batch Adam (`lr=.005`, L2 `.001`, max 300 epochs), scores whole inner groups every ten epochs, and keeps the lowest inner group-weighted log-loss checkpoint, with six-check patience. A scikit-learn histogram gradient-boosted tree uses 15 maximum leaves, 20 minimum samples per leaf, 128 bins, learning rate `.05`, L2 `1`, and fixed candidate iterations `(25,50,100,200)`. Its built-in row-level early stopping is disabled; only the four inner timetable groups select the iteration count. Tree and MLP fit/inner curves, selected checkpoints, the logistic fit information, preprocessing, model parameters and joblib tree are saved. All methods share the same 20/4/8 groups.

Outer evaluation reports fleet-weighted log loss, Brier score, average precision, fixed-half accuracy, and positive/negative recall at the same fixed half threshold, with explicit class counts/weights and null recall when a class is absent. Ranking recall takes the top `k = number of case trips`, a budget computable before solving; it does **not** use the held-out count of selected edges to set `k`. Its numerator and denominator use held-out labels solely for retrospective scoring. Per-group and per-source metrics, prediction probabilities keyed by movement ID, observed labels, and fit/inner/outer group and weight manifests are saved for independent replay. No threshold or hyperparameter is selected on outer labels. Twelve tasks are repeated folds/seeds, not 12 independent datasets or a production claim.

Each task creates an exclusive `taskNN/launch.json` before dataset load and fitting; failures retain typed `failure.json` and a failed receipt, while abrupt termination leaves at least the launch marker. No retry or requeue is automatic. A Slurm array `0–11%4` runs at most four concurrent workers, each requesting one CPU, 8 GB, 30 minutes and one numerical thread, excluding `scaglione-compute-01`. The shell cap is 1700 seconds inside the 1800-second allocation. Source commit/hashes, pool manifest, Python-library versions, model configuration, results, tree artifact and elapsed time are pinned. The isolated training interpreter is `/home/nc437/egg-route-training-env-20260930/bin/python` with scikit-learn 1.7.2, joblib 1.5.2, NumPy 1.26.4 and SciPy 1.13.1; a different version fails preflight. Root owns submission. This 32-group experiment does not alter the completed eight-group pilot or future 64/128-group checkpoints.

This exact32 prefix has all 64 source fleets. Later 64/128-group pooling must explicitly handle any source-censored group as ineligible for full-pair supervision and retain its failure/time evidence; it must neither fill missing labels nor silently discard the group. That later admission policy is outside this frozen experiment.
