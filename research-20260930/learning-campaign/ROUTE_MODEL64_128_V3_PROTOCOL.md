# Prospective exact-prefix source-route learning curves, version 3

This protocol extends the frozen 32-group source-movement classification experiment without choosing models, settings, thresholds, or a prefix from its outer outcomes. The v2 model menu, feature whitelist, seeds, logistic configuration, Adam MLP32 configuration, HistGBDT configuration, inner-only stopping rules, and fixed trip-count ranking budget are imported directly from `physical_route_model_v2.py`. The task still predicts whether a movement was selected in an observed replayed source incumbent. It does not test new-route physical feasibility, target charging economics, optimal edges, or a production route policy.

Pool only exact TRAIN prefixes `10000–10063` (64) and `10000–10127` (128). The 64 pool requires admitted shards 0–7; the 128 pool requires admitted shards 0–15, even if some later shard has already finished. The pool reads and hashes each admission receipt plus only `cases.jsonl` and `source_inputs.jsonl`; it exports no source-outcome or target table and runs no native replay. It fails before output creation if any required shard is unavailable, incomplete, or outside its fixed eight-group registry interval. Pooled manifests pin receipt, case-table, source-table, and available receipt-recorded health hashes. They report every intended timetable, its two intended source labels, actually observed source fleets, missing labels, eligibility for observed-source supervision, and eligibility for full-pair supervision. Registry groups with zero observed sources remain in the manifest and in group splits but contribute no supervised rows. A partition with zero eligible groups fails explicitly. Missing sources never receive an imputed negative label, and an entire timetable is not silently discarded.

Shard 04/base `10037` has `source0` censored and three dependent target censors; `source1` is an observed replayed source fleet. The manifest records the absent `source0`, the one observed source, and the registered three dependent target censors, with the shard-04 admission receipt and its recorded health hash as provenance. No retry or target table read is part of this pool. The base timetable remains in its assigned group partition; `source1` participates in observed-source edge classification with its own labels. It is ineligible for full-pair supervision, which is reported separately. Every later missing source receives the same explicit availability treatment.

Four outer folds use the sorted registry index modulo four. In each outer training complement, inner groups are `training[2::6]`; this gives 40 fit, 8 inner, 16 outer intended groups for 64 and 80/16/32 for 128. The frozen 32-group run remains 20/4/8. All available variants of a timetable stay in its registry-assigned partition. Each eligible timetable has equal total weight; its observed sources split that weight equally; movement rows split their source weight equally. Intended and eligible group/source denominators are saved for fit, inner, and outer partitions. Preprocessing, prevalence, and kind frequencies use fit groups only. The MLP and tree select checkpoints using whole inner groups; the outer partition is evaluated after those choices. No refit on inner groups and no outer tuning occur.

For each fold and seed (17, 29, 43), save heldout log loss, Brier, average precision, fixed-half accuracy and class recall, and trip-count-budget top-k recall. Per-source metrics are averaged within each eligible timetable, then timetables are averaged equally for the primary full-prefix metrics. This matters for nonlinear metrics such as average precision and for the single-source group 10037: the pooled legacy top-k field averages fleets and would give it half the influence of a complete pair. Save pooled-label metrics separately as secondary diagnostics. Save per-source and per-group heldout metrics and movement probabilities/observed labels, including source and movement IDs; zero-source groups have an explicit null group metric and an eligibility record. Also score the original 32 timetable subset in each 64/128 outer fold using the same per-source then per-group rule as a matched-population diagnostic alongside the full-prefix macro result. Later comparisons with the frozen 32-group run must compare common outer timetables as well as the full-prefix population, average repeated seeds within timetable before summarizing timetables, and report censor eligibility. The common-subset diagnostic is predeclared and cannot select a model or hyperparameter. Twelve fold/seed tasks are repeated measurements, not twelve independent datasets.

Use separate immutable pool and model paths for 64 and 128. Each task writes an exclusive launch marker before data load; source identities/hashes and pinned runtime versions follow; completion writes result, joblib tree, and SHA-256 receipt. A typed failure and failed receipt remain on handled errors; Slurm wrapper receipts capture timeout or other abnormal exits. No automatic retry or requeue.
