# Exact-128 CPU model-family comparison, version 5

This is one frozen, TRAIN-only comparison of three additional families for **observed feasible source-incumbent movement membership**. It uses the already admitted exact-128 TRAIN prefix (`10000–10127`), pool SHA-256 `d9aad5b5ea62fd82a8b4f6a3c20a95c57953ba12c7bf0949fa06004aa511c40d`, and its explicit source0 censor at base 10037. It does not refit v2/v3/v4, read development or sealed test data, assemble a route, or claim edge optimality. The existing 17 numeric edge features, fit-only preprocessing, equal timetable/source/movement weights, fixed input-trip-count ranking budget, four 80/16/32 fit/inner/outer grouped folds, and seeds `(17,29,43)` are unchanged. Twelve fold/seed tasks are repeated measurements, not twelve independent datasets.

The fixed two-candidate menu per family is:

| Family | Candidate A | Candidate B | Shared settings |
|---|---|---|---|
| XGBoost CPU | depth 3 | depth 6 | Histogram trees, 800 rounds maximum, learning rate 0.05, L2 1, all rows/features, inner weighted log-loss early stopping patience 50, one thread. |
| CatBoost CPU | depth 4 | depth 6 | 800 rounds maximum, learning rate 0.05, Logloss, L2 leaf regularization 3, random strength 1, weighted train/inner Pools, `use_best_model=True`, inner early stopping patience 50, one thread. |
| ExtraTrees | minimum leaf 5 | minimum leaf 20 | 300 trees, all features, no bootstrap, one thread, no early stopping. |

The same v3 group/source/edge weights are scaled to mean one for each library's fit and validation APIs; their relative values are unchanged. No additional class weighting is applied. XGBoost's sole evaluation set and CatBoost's weighted evaluation Pool contain whole inner timetables only. Their native early-stopping rules therefore observe inner weighted log loss, never outer labels. XGBoost predictions explicitly use `[0, best_iteration+1)` and CatBoost predictions explicitly use the retained `tree_count_`; the runner checks CatBoost's count against its best iteration. Each candidate's final probabilities receive an independent inner weighted-log-loss calculation using the frozen metric implementation. The lower of the two inner losses selects each family configuration, with menu order breaking exact ties. A separately reported **inner-promoted family policy** selects the lowest of those three family inner losses, with fixed tie order XGBoost, CatBoost, ExtraTrees. All three families and that preselected policy are then evaluated once on outer groups; outer metrics cannot promote a family or revise any candidate.

The pooled adapter materializes admitted rows before training, but `run_fold` excludes outer x/y from preprocessing, fitting, early stopping, and configuration/family selection. Outer arrays are accessed for scoring only after all six candidate models and all inner decisions have been saved. Each fit writes a candidate-start event with family, index, config, and timestamp before it begins, so a hard stop identifies the interrupted candidate. Each completed candidate is serialized and SHA-256 recorded **before the next candidate**: XGBoost JSON, CatBoost CBM, and version-pinned scikit-learn joblib for ExtraTrees. Candidate evidence retains its tuned config and complete JSON-normalized `get_params()`, fit/inner metrics, selected/stopped iteration and weighted inner curve when applicable, elapsed time, model format, and hash. The task saves fit/inner/outer group IDs, eligibility, fit-only preprocessing, per-source and equal-timetable outer metrics, movement-keyed probabilities and observed labels, the original-32 common subset metric, all candidate and promotion receipts, runtime versions, source hashes, and wall time. A missing pinned library or failed fit is a typed failed task, never a silently omitted family. A partial task's prior completed candidates remain inspectable without automatic resume or retry.

The package uses an exclusive task directory and launch marker before source hashing or data load. The successful receipt hashes the result and every saved candidate/inner decision; handled failures retain elapsed time and hashes of completed candidates. A hard kill may leave only launch/progress artifacts plus wrapper/Slurm accounting. No requeue or automatic retry is configured.

The prospective array is `0–11%4`, one requested CPU and 8 GB per task, 30-minute Slurm allocation, 1700-second child cap, one numerical thread (including prediction), no requeue, and excluded node `scaglione-compute-01`. At most four tasks run concurrently and the 12-task request totals at most six CPU-hours; tasks exit when done. The isolated interpreter `/home/nc437/egg-route-family-env-20260930/bin/python` pins XGBoost CPU 3.0.5, CatBoost 1.2.8, scikit-learn 1.7.2, NumPy 1.26.4, SciPy 1.13.1, and joblib 1.5.2; its environment receipt and lock are source-pinned. Result path: `result/physical_learning/20260930-route-model128-families-v5`. Root owns submission, collection, and later saved-model replay.

The API choices follow the [XGBoost 3.0.5 Python API](https://xgboost.readthedocs.io/en/release_3.0.0/python/python_api.html) for `sample_weight_eval_set`, early stopping, and `iteration_range`, and the [CatBoost classifier fit documentation](https://catboost.ai/docs/en/concepts/python-reference_catboostclassifier_fit) for weighted validation Pools, `use_best_model`, and `early_stopping_rounds`. The comparison is exploratory model research. Better edge classification alone does not demonstrate a legal whole-fleet proposal, a lower target bill, or solver speedup.
