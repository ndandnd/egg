# CPU route-model pilot launch review

Root and Luna reviewed the feature construction, grouped splits and task isolation. Predictors are the 17 declared numeric case/movement/source-price attributes. Observed source-plan membership is used only as incumbent supervision; IDs, selected-plan topology, target costs, solver status and bounds are excluded from predictors. All source variants and movement rows of a base timetable share a fold. Preprocessing and cheap controls use only six training groups; the other two groups are evaluated after a fixed 240-epoch fit. Three seeds vary the MLP, not fold membership; deterministic linear/control repeats are not independent statistical evidence.

Sol's final focused suite reports seven passes, plus Python compilation and shell syntax checks. Root reviewed the final launch-marker and failure handling: the exclusive task directory and launch receipt precede data loading/fitting, failures preserve elapsed time/traceback, and an existing task cannot be rerun. Saved model/config/preprocessing, per-movement held-out predictions and labels, group metrics, training curves and hashes support later independent metric replay. Neither reviewer ran the real pilot locally.

The declared array contains twelve tasks with concurrency four. Each requests one CPU, 8 GB and 30 minutes, with one numerical thread, a 1700-second shell cap, no requeue and exclusion of scaglione-compute-01. Combined with up to eight label workers, the requested ceiling is 12 CPUs and 96 GB. Root owns the single guarded submission and collection. This is an exploratory eight-group movement-classification pilot; it does not yet produce verified feasible routes or establish cost/time improvement. Development and sealed tests remain untouched.
