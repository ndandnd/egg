# Exploratory physical source-route scorer: eight-group CPU pilot

This is a **TRAIN-only** source-fleet supervision experiment on the admitted shard-00 v2 composite. The two source fleets for each of eight independent timetables supply 16 observed feasible plans and 7,560 candidate movement rows. A positive label means a movement appears in an observed feasible source incumbent. A negative label means it was unchosen in that incumbent; it does **not** establish that the movement is infeasible or poor. Source solves include time-limited incumbents. Charging outcomes, direct or curved costs, certificates, solver status, group IDs, plan hashes, and dev/test cases are excluded from features and fitting.

The explicit 17-number feature policy is `learned_proposals.FEATURES`: four movement-kind indicators; scaled start, end and duration; scaled movement/before/after energy; scaled charging-window duration; source-market window mean/min and market mean/spread; same-place indicator; intercept. These use only the frozen physical case and source-market tariff known before source solving. IDs, names and row positions are join keys, never numeric predictors. The trainer reads only `cases.jsonl`, `source_inputs.jsonl`, and the admitted dataset receipt, pinned at SHA-256 `c9ed1e67356812e60a5986153227029d8eb15e98e2799a0ef87a56284be671d7`. It checks table hashes, TRAIN group registry, case/source market identity, full-plan hash, selected movement set, and path-cover structure. It never opens `target_outcomes.jsonl` or reserved groups.

The fixed task grid is four grouped outer folds (two held-out timetables each) crossed with seeds 17, 29 and 43: array IDs 0–11. Both source variants of a timetable remain together. Within each task, six groups train all models; the held-out two groups are evaluated once at the end. Mean/scale, class prevalence, and per-movement-kind frequencies are fit only on those six groups. Each fleet has equal training weight. Controls are global selection prevalence and training-only frequency by movement kind. The learned models are L2-regularized linear logistic and a 16-hidden-unit tanh MLP with NumPy full-batch gradient descent. Each runs a prespecified 240 epochs at learning rate 0.03 and ridge 0.001; there is **no hyperparameter selection or early stopping on outer held-out groups**. Training loss/Brier/accuracy curves are saved at epoch 1 and every 20 epochs. Held-out weighted log loss, Brier, accuracy, positive/negative recall, and each held-out group's source-specific metrics are saved. No test-set, native solve, repair, price selection, or online-speed claim follows from these edge metrics.

Each array worker first creates its own exclusive `result/physical_learning/20260930-route-model-pilot/taskNN` directory and launch receipt, before loading data or fitting. It saves model/preprocessing/metric result and receipt with dataset receipt SHA-256, input-table hashes, source commit/hashes, NumPy version, full fixed training configuration and elapsed time. Held-out probabilities and observed labels are serialized by group, source and movement ID as **evaluation artifacts** so metrics can be independently recomputed; those IDs never enter the model matrix. An exception leaves typed `failure.json` and a failed receipt. An abrupt kill leaves the launch marker at minimum; neither path silently retries. A separate Slurm wrapper receipt records task/job/return status. Up to four array tasks run concurrently; each requests one CPU, 8 GB and 30 minutes with one numerical thread, no requeue and exclusion of `scaglione-compute-01`. The shell cap is 1700 seconds inside the 1800-second allocation. Root owns submission and collection.

The eight-group pilot measures whether either model improves held-out **movement classification** over cheap controls across independent timetables. The 12 runs are repeated seeds/folds, not 12 independent datasets. Their fold models are exploratory artifacts, not a production predictor. The later 32/64/128-group pooled-fit checkpoints remain; the explicit user request starts CPU training now while independent label shards continue. Any eventual route proposal must be decoded or projected, physically replayed, and separately verified under the target market before use.
