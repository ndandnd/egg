# Independent recovery integration code review

23 October 2026. Static review of the current diff in `src/egglab/native_pathflow.py`, new `src/egglab/recovery_lift.py`, and `src/tests/test_recovery_interface.py`. No source edits, tests, solver calls or sealed-data access. The implementation agent reports 51 focused tests passing; this review does not independently reproduce that count.

**Recommendation: fix two error-path defects before native qualification.** The physical lift and binary hint design are otherwise consistent with the intended boundary. Findings refer to the inspected working copy; line numbers may move.

## Findings

**[P1] Logging/capture failures can escape and prevent return of an admitted fallback.** In `native_pathflow.py:777–796`, the `native_status` callback and `capture_incumbent`/`native_incumbent` callback execute outside either protected search or candidate block. Failure callbacks at lines 773–774 and 842–844 can also raise from inside an exception handler. A raising recorder (for example a write failure) or failed incumbent capture therefore causes `solve_planner` to raise even after `best` was admitted. The admission callback at lines 728–734 additionally shares the physical-lift exception scope: a recorder error can mislabel a valid fallback as rejected, then the rejection callback may itself escape. Existing tests omit `record`, so they do not cover this boundary.

Requested correction: separate physical admission from diagnostic emission and ensure diagnostic/capture exceptions cannot prevent a structured fallback result. Preserve the error in a safe in-memory ledger when external recording fails. A meaningful solver-free test injects a recorder failure at `native_status` and an incumbent-capture failure after fallback admission, then checks the physical plan and true bill still return.

**[P2] Early retention of an improved physical bill can leave a reversed returned enclosure after a contradiction.** At lines 805–806 a newly admitted physical candidate replaces `upper`/`best` before comparison with the previously accumulated `lower`. If a previous round gave lower=50 and a later independently valid candidate gives true bill=40 with its own acceptable current-round bound, line 837 detects the cross-round inconsistency and raises. The handler at lines 840–846 retains lower=50 and upper=40, labels the result `bounded`, and exits before the later invariant check. The final result then exposes a negative gap. Keeping the physical plan is right; continuing to advertise the contradictory old lower as an enclosure is not.

Requested correction: on a contradiction retain the best replay-valid plan, invalidate/quarantine the inconsistent certificate and return an explicit contradiction status with no claimed valid enclosure. Add a two-round injected-statistics test; it does not require a native solver. This is an error-path issue, not evidence that normal numerical bounds are wrong.

## Boundaries that look correct by inspection

- `lift_plan` validates both cases, compares physical/policy fields, checks movement and trip identities, recovers source/full paths, deep-copies physical events and independently replays both domains. It recomputes the target-market bill and does not import a restricted bound. Global lower bound is explicitly `None` in lift provenance.
- `_attach_pricing_start` inventories all compact binary variables and supplies each movement's zero/one value through `model.start`. It does not fix binary bounds or seed continuous variables. Fixed-topology completion intentionally fixes bounds later on its own model; that existing step is distinct from recovery submission.
- `_shared_deadline` uses the minimum of caller absolute monotonic deadline and local budget. Setup stages check that same deadline; native optimization/completion receives it. This prevents a fresh optimization allowance. Physical validation, model construction, extraction and logging are not interruptible and can overrun; the final timing reports overrun, so qualification must retain an outer end-to-end timeout rather than promise a hard Python wall-time cutoff.
- A valid physical fallback survives the specifically protected build, start-attachment, optimization, no-incumbent and candidate-extraction paths. Infeasible full-model status while holding a valid fallback is explicitly a model/replay contradiction.
- Candidate ranking uses recomputed physical true cost. Completion keeps original full native MIP bound provenance and substitutes only the completed candidate incumbent for admission; a fixed-route LP lower bound is not used as a global certificate. This remains true only when the caller actually supplies the intended full case—these APIs cannot infer campaign intent.
- The default no-start path is largely preserved, but this diff also changes no-start status after a later infeasibility and adds setup deadline checks. Existing no-start regression coverage should be retained; the newly added tests primarily cover the recovery path.

No proof of solver start acceptance is present or claimed: `submitted` with solver status `unknown` is appropriately weaker. Native qualification still needs to exercise actual start compatibility, full-case replay/billing, absolute timing, and original-model bound provenance after the two defects are corrected.

## Resolution review — 23 October 2026, after integration fixes

**Both findings are resolved in the inspected working copy; no remaining blocker identified in this narrow re-review.** The original findings above are retained as the audit history. This is static verification of the fixes and added fault tests, not a native qualification or independent rerun of the reported 57-test suite.

- **P1 resolved:** `solve_planner` now wraps the recorder and stores sink exceptions in `instrumentation_failures`, so failure callbacks cannot rethrow ordinary diagnostic errors or relabel physical admission as rejected. Incumbent capture now runs inside the candidate exception boundary. New parametrized tests inject failures at `native_status`, `native_incumbent`, `recovery_fallback_admitted` and `candidate_rejected`; a separate test injects incumbent-capture failure. They check preservation of the admitted bill and unbounded certificate status. By inspection these cases exercise the previously unprotected paths.
- **P2 resolved:** cross-round enclosure contradiction now records prior/current values, invalidates the global lower to negative infinity, and returns `bound_replay_contradiction` while retaining the improved physical upper. A final return-time invariant also quarantines a reversed retained enclosure if an earlier reconstruction exception bypasses the main comparison. The new two-round injected inconsistency test explicitly checks upper=27, lower=negative infinity, gap=positive infinity and contradiction status, with previous lower=50 preserved in the diagnostic ledger.

The tests correctly use artificial admission/statistics inconsistencies to isolate fault handling; they are not claims that such values form valid physical solver bounds. No source files were edited and no tests or solvers were executed during this re-review. Proceeding to bounded native qualification is reasonable, subject to its separate timing, start-compatibility and physical-replay gates.
