# Launch-prefix source review

24 October 2026. Independent source-only review of the new initializer, its new
handwritten-metadata tests, protocol/implementation/wrapper notes, and the driver
diff from the reviewed launch-accounting gate. No Python imports, tests, native
work, research-data parsing, or commits were performed for this review.

No arithmetic or persistence blocker was found in the reviewed scope. The
initializer rebuilds the supplied frozen accounting record with the checked
builder and rejects a forged record or an inexact final addition before mkdir.
The explicit base2**-53 / target1+2**-52 test covers the underfunding case without
tolerance or clamping. Publication uses exclusive new-directory creation and the
actual runner's exclusive campaign writer and hash-linked ledger appender;
failures retain the partial namespace, which cannot be reused.

The campaign object has exactly q.run's five keys. The carry event uses the
canonical subtraction-derived freeze component, and the following supervisor_cpu
event funds the separate external correction. The real q.resume_state consumer
starts from carried+freeze and then folds that correction in the same order as
the prepublication exactness check. Its readback must return no completed tasks
and exactly the supplied reconciled total before the flat informational receipt
is published. The new tests cover actual consumer compatibility, raw-component
rejection, zero/nonzero correction, immutable inputs, malformed/forged metadata,
existing-byte preservation and retained partial publication.

Campaign references and digests remain explicit caller-supplied metadata. In
particular, the freeze_receipt string must be the canonical resolved path used by
q.run; accepting an absolute reference here does not authenticate that path or
its bytes, and cannot establish that a future lock/receipt will match it. This
does not weaken the declared metadata-only scope or grant launch permission.

The driver diff changes scope, namespace, carry, selected test and inherited
accounting bindings; monitoring/ownership/cleanup and charge computation bodies
are preserved. Carry1521.155429840183, ADMIN0, package20 ending1541.155429840183,
work10/outer12.5/inclusive15/closure5, one thread and 5GiB match the protocol. Only
the new initializer test is selected. Prospective command/budget artifacts still
require the parent's final read-only binding check before the sole invocation.

A passing gate can establish publication/consumer compatibility on these examples
only. It provides no provenance authentication, numerical qualification, CF1
mechanics clearance or authorization for another native attempt.
