# Responsive v6: one bounded fake-execution source gate

This prepares one source gate, not a primitive, metadata lock or native launch.
The parent must wait for stable implementation/tests, review the source, then
run `responsive-supervision/prepare-source-gate.py` once in the metered Python
batch to create the exact prospective budget and source/command manifest. No
peer computes hashes, imports project modules or runs tests during preparation.

The exact gate child is the repository `.venv-local/bin/python -m pytest -q
src/tests/test_responsive_supervision_v6.py`; the manifest command is the
absolute two-element invocation of `run_responsive_source_checks.py`. Only the
new test executes; no historical matrix or qualified old test is selected.
The nine legacy tests required by the existing v6 source consumer are hashes
only: the eight inherited qualified dependencies and the v5 entry test.
Current full `q.campaign.sources()`, the new test, design/failure/implementation
notes, core integration note, this protocol, budget adoption and all three source
gate/preparation/finalization scripts are bound upfront. The command manifest
omits only its own digest; the actual attempt inventory records that digest.
