# Static parent-driver handoff

`run.py` owns one fresh canonical `attempt01/`. It consumes the frozen `COHORT.json`, `PREPARATION_ACCOUNTING.json`, `PROTOCOL.md`, `LAUNCH.json`, eight explicit local source files, and the two literal pinned TRAIN JSONL tables. It does not reread the older coherence/FIT/metadata receipts: the closed selector's exact path-to-digest map and source-receipt backreference are checked as inherited provenance, without following those paths. COHORT selects eight groups by the fixed ID rule before copying cost scalars. No model assets, case generation, scoring or optimizer call occurs in the parent.

The two tables are each streamed and SHA256-hashed once, with 512 MiB/file and 16 MiB/line caps. All TRAIN lines are transiently JSON-decoded for top-level routing; nonselected groups are immediately discarded without further semantic inspection. Only eight selected cases and their sixteen original source plans persist for worker specs. Case/default identities, TRAIN/profile/service joins, whole original plan digests, selected-ID membership, market identity, original independent replay and all four exact baseline costs/Ebar are checked before dispatch. Source replay caches are never consulted. Any malformed, duplicate, missing, identity, pin or replay finding prevents dispatch; there is no replacement or repair. Same-membership controls must have the same canonical multiset of ordered trip/movement paths up to vehicle labels.

Each of the 32 frozen tasks has an ordinal folder `001-cell` through `032-cell`; opaque task IDs never become paths. Every folder contains `spec.json`, its SHA256 in the external receipt, an exclusive incomplete `receipt.json`, stdout/stderr, and eventually `external-receipt.json`. The worker receives the whole original raw case/plan, explicit target coefficients and identities, and exact-string `baseline_F_exact`/`original_Ebar_exact`. Worker outputs are separate `best-plan.json`, `brief-replay.json` and its compact receipt. Parent output is `attempt01/{preflight.json,receipt.json}`; all assignments survive funding/fatal stops as unattempted records. No automatic retry or resume is supported.

The launcher copies the existing local stdlib harness pattern, with an explicit `worker.py` path instead of rebinding another campaign. The anchor precedes Popen; final allowance is 60 seconds, native cutoff 52 inside the worker, and the child has CPU hard limit 90 seconds. Only the still-unreaped direct owned child is terminated/killed during the three-second cleanup; an unreaped child retains a 90 CPU-second funding reserve and stops subsequent dispatch. Parent admission requires reaped exit zero, no timeout/launcher/fatal failure, complete worker receipt, worker acceptance, and the complete JSON read finishing within the same 60 seconds. A worker's own earlier timestamp is insufficient.

The closed StageA retained CPU charge is added once to cumulative parent plus waited-child CPU. Dispatch funding is `StageA + self + waited children + unresolved reserves + 90 <= 3240`; total package is 3600 CPU/7200 wall with 360 CPU closure reserve. StageA plus main preflight must remain within 120 CPU; finalization has a 120 CPU bound inside the same total. No per-child CPU delta is added again to cumulative waited CPU. Missing/failed preparation accounting is failclosed. Historical global costs are separate and do not reset or consume this prospectively bounded package again. Actual external meters remain necessary to include receipt publication and exit.

The master retains complete compact worker diagnostics, native point/status/bound attempts, physical candidate versus retained-fallback flags, and parent timing/qualification separately. Group readout gives exact qualified point differences by target market and canonical controls. Every mathematical route-optimum ordering is explicitly unresolved: native OPTIMAL, nullable raw ObjBound and source-point agreement do not supply a justified optimum-gap interval. This note grants no launch authority. No imports, compilation, tests, data reads, hashes or solver execution were performed during source preparation.

The narrow integration closure explicitly bounds finalization to180 wall seconds
and rearms a total-wall/publication timer even after an earlier dispatch alarm,
without clearing a latched stop. A call-less non-timeout model/copy bootstrap
failure or unexpected helper-interface exception is fatal for later dispatch:
the original physical fallback does not qualify an incompatible new model.
