## Current proposal inputs and tariff paths

Both public scoring entry points accept `case, prices`, with **no `b` argument**. GNN `v8_scores` constructs `edge.edge_features(case, prices)` and `graph.topology(case)`, then standardizes using `mean_fit_only`/`scale_fit_only` and scores the graph. CatBoost `score_case` uses the same edge features and standardization before `RawFormulaVal` prediction. See [GNN entry](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/experiments/codex_local_campaign.py:153) and [CatBoost entry](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/experiments/codex_train_classical.py:51). In the declared training loader, `prices` is explicitly `market.a`; this review does not trace a different caller's argument binding.

The shared 17-column schema, in order, is:

`pullout, direct, depot, pullin, start_time, end_time, duration, movement_energy, before_energy, after_energy, charge_window, window_price_mean, window_price_min, market_mean, market_spread, same_place, intercept`.

Exactly four columns directly depend on the supplied tariff: zero-based columns **11–14**, `window_price_mean`, `window_price_min`, `market_mean`, `market_spread`. Window mean weights `a` by market-period overlap with a depot or terminal charging window; window minimum uses positive-overlap periods. **Other movement kinds and empty windows still receive global mean/minimum**, so removing only charge-window prices on charging edges leaks `a`. Global mean and max–min spread appear on every edge. Other columns use movement/adjacent-trip geometry and energy, horizon/battery scaling, movement kind and an intercept. No direct quadratic coefficient feature appears. See [schema](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/learned_proposals.py:19), [window calculation](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/learned_proposals.py:67), [feature construction](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/learned_proposals.py:85).

GNN topology itself uses sorted trip IDs and movement endpoints, preserving parallel modes; its two node-role flags distinguish depot source/sink. Neither function reads tariffs. However, standardized edge `x` is aggregated into **initial node states**, encoded into edge states, propagated through attention/messages, and included again in the final decoder. A blind branch must remove/neutralize all four tariff coordinates **before any of those operations**, with its own fit-only transform; masking only the decoder is insufficient. Group/source strings are used for batching weights when labelled, not passed as model covariates. See [topology and batching](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/physical_route_graph_v6.py:43), [model forward](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/physical_route_graph_v6.py:157).

Fit preprocessing is per-column mean/std, with a fixed intercept and tiny-scale guard; retained physical columns are not algebraically normalized by tariff columns. Nevertheless, blind preprocessing must be recomputed from its permitted fit inputs, not borrow price-derived transforms or cached embeddings. Timetable/physical inputs may correlate with historical tariffs; current-case tariff blindness does not imply statistical independence or absence of historically learned price information. See [preprocessing](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/physical_route_model_v2.py:146).

## Actual training source and target

The common loader accepts the pinned exact128 TRAIN pool and joins `cases.jsonl` to `source_inputs.jsonl` by group. It checks `base_group`, `base_id`, `split`, `generator`, `physical_profile`, `case_identity`, then source kind, source-plan hash and market identity. **Inputs are `edge_features(case, market.a)`; targets are binary membership of movements in the observed `source_plan`**, not an optimality label or cost-sensitive target. `selected_vector` checks the selected topology via `recover_paths`. See [loader](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/physical_route_model_v3.py:28), [input/target construction](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/physical_route_model_v3.py:63), [target encoding](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/learned_proposals.py:116).

The source declares `source0`: constant `a=.20`; `source1`: `.10` at periods 18–21 and `.30` elsewhere; both have constant `b=1/900`. Thus the intended training setup has within-timetable **a variation**, but no b variation. This does **not** establish that both sources were observed for every fit group, that their binary targets differ, or that a proposal gains from conditioning. Manifest eligibility can establish source-pair availability; it cannot establish target differences without separately authorized label access. See [market definitions](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/physical_learning_cases.py:191) and [eligibility validation](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/physical_route_model_v3.py:85).

The v8 training entry delegates to `physical_route_graph_budget_v8.run_fold`, which uses the same v6 loader/model functions, grouped fit/inner/outer split and fit-only normalization. It saves the transform and groups, chooses states/architecture using inner data before outer evaluation, and records source identity separately. CatBoost training checks that same task00 split and transform, fits on fit rows, uses weighted inner early stopping and candidate selection, and exports preprocessing plus provenance metadata. Exact128 split sizes are 80 fit / 16 inner / 32 outer. See [v8 entry/provenance](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/experiments/train_physical_route_graph_budget_v8.py:71), [v8 training](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/physical_route_graph_budget_v8.py:252), [group split/weights](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/physical_route_model_v3.py:108), [CatBoost training/export](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/experiments/codex_train_classical.py:83), [inner early stopping](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/src/egglab/physical_route_model_families_v5.py:104).
