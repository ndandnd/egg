The fixture creates `prices[station]` with **integer** hour keys `0..25` ([fixture.py:37](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/research-20261026/adjacent_bridge_qualification/fixture.py:37)), and includes that mapping unchanged in its descriptor ([fixture.py:57](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/research-20261026/adjacent_bridge_qualification/fixture.py:57)). Trip-time/energy maps also have integer keys, but their `0..5` domain alone would not expose the ordering problem.

Admission stores the in-memory descriptor as `bank['fixture']`, then `write` uses `json.dumps` ([worker.py:346](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/research-20261026/adjacent_nonlinear_pilot/worker.py:346)). JSON object keys are strings: after the context's `json.loads`, hour keys are `"0".."25"`.
3. `canonical` is `json.dumps(value, sort_keys=True, separators=(',',':'), allow_nan=False)` ([worker.py:68](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/research-20261026/adjacent_nonlinear_pilot/worker.py:68)). It sorts the Python keys **before** encoding them. Fresh fixture integer keys sort numerically; loaded bank string keys sort lexically. Thus fresh hour order begins `0,1,2,...`, while loaded canonical order begins `"0","1","10","11",...`. A minimal illustrative submapping with keys `2` and `10` serializes in numeric order before a round trip, and in `"10","2"` order afterward. Equal hour-to-value content does not make these serialized strings equal.
4. The context regenerates the literal descriptor and compares these two different representations by serialized-string equality inside the composite guard ([worker.py:354](/Users/nadan/Documents/ChatGPT/egg/ml-prediction-20261017/research-20261026/adjacent_nonlinear_pilot/worker.py:354)). Consequently that fixture comparison fails even for an unchanged correctly serialized bank. A matching file digest authenticates the consumed bytes; it does not make this comparison invariant under JSON key conversion.

This is a serialization-boundary defect, not evidence that the admitted physical bank or economic model was invalid. No native optimization result exists to interpret from the reported failed context. The source explanation does not establish the actual file's other contents, nor exclude an additional policy/admission discrepancy inside the same composite guard; those remain uninspected. Subject to the stated frozen-source and unchanged-publication assumptions, the ordering defect alone already predicts the reported guard failure.
