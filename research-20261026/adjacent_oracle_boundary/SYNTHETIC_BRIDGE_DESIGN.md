## First executable question to freeze later

Can EGG pass one wholly synthetic in-memory problem through the actual adjacent
capacity-aware **fixed-duty** and **route-changing** interfaces, preserving the
same service, price, station physics and honest certificate tiers? This is an
oracle-connection diagnostic, not evidence that one regime needs learning or
that Partille physics has been reproduced. It does not rerun the native toy
coefficient benchmark.

Begin in the posted-price limit, which is what these sibling interfaces optimize.
The route master uses additive linear column costs; it does not optimize EGG's
aggregate strategic payment or integrated quadratic procurement merely by
re-costing each route separately. Nonlinear valuation may stay in EGG as an
explicit post-evaluation lens, with no nonlinear-optimality claim. A genuine
nonlinear outer master/deviation interface remains a distinct later integration
question, not an implicit capability of this bridge.

## Literal in-memory authority, with no private-data dependency

A later prospective input must be one NEW source-defined fixture, with no
`build_problem` call, GIRO CSV/workbook, reference schedule, old journal, TRAIN
row, model asset, sealed bank or synthesized value chosen after solving.
The exact numeric literals are not selected by this note. Freeze them and their
complete allowed fields before any generation or optimization.

The sibling `ProblemData` fields are `frame,trips,adjacency,start_min,end_min,
trip_energy` (`audit_giro_known_columns.py:65–72`). Its pricing path consumes the
named nonframe attributes in the inspected constructor/record interfaces; the
caller must nevertheless supply `frame` explicitly rather than silently treating
it as unused in every transitive interface. Each adjacency item is
`(successor,travel_min,deadhead_kwh,kind)`. Recognized kinds are trip_trip,
trip_station,station_trip,depot_trip,trip_depot,station_depot
(`event_pricer_network.py:252–273`). Values are synthetic, not copied private
operating records.

No general frame/export schema is established by that narrow fact. A future
literal fixture must declare its explicit frame, index/columns/dtypes and joins
to the trip maps; this initial composition calls no CSV builder or frame export.
An added frame consumer would need its own explicit source/field admission,
not an assumption that a placeholder matches GIRO's schema.

The current constructor imports registered depot/station tokens and
HORIZON_MIN1560, not arbitrary labels or a caller-supplied horizon. A tiny fixture
can use a declared subset of those tokens as synthetic roles while supplying
tariff coverage for the full registered station set. Their names do not turn
the fixture into real Partille operating data. Preserve all transfer definitions
explicitly; do not infer missing movements. Freeze battery/initial charge/reserve,
SOC step, event block step, station-specific rates, plugs and aggregate return
target independently of outcomes. No translation from NativeCase is assumed.

Use two nonempty predetermined duties covering a small trip set exactly once.
As an outcome-independent fleet witness, declare two positive-duration service
trips that overlap in time: no vehicle can perform both. With fleet cap2, any
feasible exactly-once route-changing selection then has two vehicles. The
fixed-duty filtered graph also requires one whole path per duty. This uses the
existing fleet-cap/fleet-first master without inventing an exact-N argument.
It does **not** establish feasibility: power/SOC/plug constraints can still
prevent a selection. Record the overlap facts from the frozen fixture, actual
fleet results and failure states, rather than choosing the cap from solver
outcomes. The observation is classical, not a new lower-bound theorem.

Select prospective session fee0 and retain sibling BUS_COST_KX1e5. Do not replace
it silently with EGG's synthetic100. Under the independent common fleet witness
it is a common surrogate; subtracting it for a charging-cost display must not
change master objective semantics. Station tariff dictionaries are posted
linear quotes. Any background-load/economic coefficient inputs for EGG cross-
valuation remain separately named and do not reduce physical charger capacity.
No dollar calibration, outage frequency or empirical price-impact claim follows.

## Calls and controls, using one loaded provider

The caller's admitted by-reference boundary supplies the registered
`CapacityTerminalNetwork` class and common `run_capacity_terminal_cg.run`
callable; no second importer or copied solver is introduced. Pass that class
to `make_fixed_duty_network_type(base_type,duties)` for the fixed-duty arm.
The factory validates duties before parent graph construction and filters only
inherited source/direct/charge generators. It keeps every inherited admissible
station/time/energy alternative and the original record/replay path.

Construct separate networks for the two arms from the **same** literal problem,
station prices, station-power map, plug counts, SOC/event grid, initial/reserve
and terminal target. Use `partition=True`, fleet_cap2 and `seeds=()` in the same
`run(...)` API. Set optional diving, smoothing, partial pricing and integer-aware
pricing off for this minimal boundary diagnostic. Fixed duty permits changes
of charging station/time while preserving each whole service sequence; the full
arm may reassign trips. Confirm returned full sequences independently. Do not
use the old cost/energy frontier plus plug rows as the fixed-duty comparator.

The not-yet-frozen execution bootstrap needs a fresh isolated paid process,
explicit zero start-fee arguments/import order and the registered source path;
load the capacity runner before modules that capture fee globals, then check
captured fees and source origins. Boundary code takes those already loaded
objects by reference and does not supply or qualify that importer. No current
source-only PASS implies runtime import/license/data-I/O compatibility.

The direct run API creates its own exclusive output directory and writes logs,
column journal, summary and selected routes when available. Freeze owned paths
and narrow output fields prospectively. Retain every attempted arm; no seed
import, failed-arm replacement, free extra call or alternative fixture. With
nonuniform power, existing code refuses external seeds anyway. All graph build,
cold import, dependency checks, frontier/pricing/master work, validation and
publication are paid; no comparison uses prebuilt graph time as if it were cold.

`cg_seconds` and `mip_seconds` do not form a hard total. In particular, the
existing closure re-solves can request300 seconds beyond CG expiry. A future
exact budget must use an already established externally bounded process with
paid finalization/cleanup and explicit late/unresolved status. Do not copy or
silently alter the sibling loop to fit an assumed EGG60-second envelope. No
time/CPU allowance or command is granted by this design note.

## Required result separation

Keep these layers separate for each assigned arm:

- Construction/import/admission status, all failures and paid process resources.
- Physical individual-route realization and actual exact-once duty/service
  coverage; fleet count and aggregate terminal-energy satisfaction.
- Expanded-grid plug occupancy at conservative minute resolution and selected-
  fleet shared-capacity checks; not merely individual-route SOC replay.
- Expanded-grid master cost and charging records/terminal energy versus
  continuously realized cost, charge energy and terminal SOC. Do not erase
  rounding/discarded energy or call continuous-cost pricing certified.
- Completed capacity-LP pricing/row certificate and tolerance versus incomplete
  RMP status; finite generated-pool integer bound/gap versus full route-space or
  continuous physical claims.

A missing integer selection is not proof of full-model infeasibility. A pool
OPTIMAL status is not a full integer oracle certificate. An available feasible
point may still be reported when a certificate is incomplete, with its scope
intact. Compare costs only with matched declared physics and actual common fleet;
missing operands remain undefined rather than replaced by0 or an available-only
mean. One synthetic base and repeated price/arm conditions are not independent
operating days or generalization evidence.

The first useful outcome is whether the **actual adjacent interface composition**
preserves these contracts on a source-frozen toy, including the fixed-duty
capacity alternatives that an old static frontier discards. A numerical tie or
failure is retained, not tuned away. No claim of economic necessity, novel
capacity mathematics, neural value or faithful multi-station empirical benchmark
is licensed by interface success alone.
