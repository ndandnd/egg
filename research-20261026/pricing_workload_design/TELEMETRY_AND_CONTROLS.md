## Independent discovery is the primary conventional comparison

Use independent cold fixed-duty and full networks, each with its own bank. The fixed arm retains complete assigned duty sequences through the existing three-generator restriction; the full arm uses the same physical universe without that restriction. Match fleet/partition/terminal requirements, station powers/plugs, tariffs, discretization, native settings and paid process budgets. Initialization must remain feasible for each declared arm; any supplied common incumbent must be admitted under that arm rather than silently supplying full-route information to fixed-duty discovery.

Keep the two independent banks separate until each primary endpoint and its costs are closed. Record each arm's graph setup, initial-column construction/admission, LP/row generation, pricing, integer selection, physical admission and publication. A shared union bank may later diagnose selection/search coverage, but is not either arm's standalone acquisition result. A full-universe minimum reduced cost and fixed-duty minimum are also minima over different feasible column sets; a better full minimum is not a faster solver claim.

If the future choice is `fleet_cap=4`, passing that argument to the sibling runner creates a real native `sum x <= 4` row at [69](/Users/nadan/Documents/projects/demandresponse/.codex-work/capacity-packed-20261001/src/run_capacity_terminal_cg.py:69). It is not merely an external admission check, and it is **not** exact N=4. The runner's integer stage minimizes fleet first and then imposes the attained cap before charging-cost minimization. [Two stages:333](/Users/nadan/Documents/projects/demandresponse/.codex-work/capacity-packed-20261001/src/run_capacity_terminal_cg.py:333). Exact common N needs a separately declared outcome-independent lower-bound witness or an explicitly reviewed equality policy; silently changing only a wrapper's fleet check does not impose a native row.

For end-to-end CG, each arm generates its own endogenous dual sequence. Comparing average per-call times from those different sequences confounds algorithm cost with query difficulty, phase mix and number of active capacity rows. Report whole discovery effort first. Do not call one arm faster merely because it terminated with fewer calls, missed a certificate or delivered no fleet.

## Minimal instrumentation only if the question requires it

Existing worker clocks plus history suffice for a first **whole-discovery** workload description. Do not add a monitoring process, controller, copied CG loop or new adapter for that purpose.

If exact physical batch-call CPU/counts and identical-query comparisons are necessary, the smallest separate experiment is an explicit EGG-local caller of the existing `capacity_terminal_batch` API. Before queries, freeze one common sign-consistent dual workload, objective, output limit, linear quote and query order independently of new timing outcomes. A tiny caller can record query/arm ID, start/end monotonic and process CPU, exact supplied duals/objective/limit, completion/exception state, returned count/minimum rc and existing capacity stats. Enter the attempted-call record before invoking the method and close it in `finally`; an interrupted call is not omitted. This instruments only its own explicit calls, not hidden calls inside `run`. No such code or workload is created/authorized by this note.

Under a separately chosen matched-query design, compare fixed/full oracle responses on the **same** query inputs. Preserve network construction cost and only reuse an unchanged-quote network over a prospectively fixed workload. Such a microbenchmark answers conditional pricing effort, not complete CG convergence or end-to-end routing value; it is not the selected cached control above and is not required before using existing whole-run telemetry. It cannot replace the independent cold discovery controls. Do not infer missing trip/plug dual vectors from summary scalars or invent native optimize counts from pricing-event rows.

## Chronology, qualification and denominators

Freeze acquisition, workload order, cache provenance, allowed reuse, budgets, native/outer endpoints, stopping/qualification and comparison criteria before execution. All source/setup/acquisition failures and abandoned phases consume the same inclusive chronology as successful methods. CPU is parent self plus waited children without overlapping stage totals added twice; wall includes imports, network construction, pricing reconstruction, cache I/O, selection, replay and complete endpoint publication. Native limits alone are not end-to-end deadlines. Parent chooses actual resource numbers and any scientific thresholds.

Every planned base/arm/target or query stays in its denominator. Preserve attempted/completed/late/unattempted calls, empty batch/no route, cache miss, negative-but-duplicate column, LP not optimal, artificial mass remaining, tolerance-based stop, missing integer selection, physical rejection and resource failure separately. A failed fixed-duty discovery is not silently scored as zero effort or equal cost; a retained operational incumbent is not a successful discovery/certificate. Report paired method-qualified outcomes only when both satisfy the frozen criterion, operational fallback outcomes separately, and planned/defined counts together. No available-only speedup or pooled independent-sample claim from queries sharing one physical base, bank or CG trace is justified.
