# Prospective generated-input authority

This is a static schema and path decision. It admits no current artifact values
and is not an executable launch. The future FROZEN controls bind this file and
the constructor/worker/owner sources to one reviewed revision. There are no
external data inputs: no old journals, cases, TRAIN, GIRO, plans or models.

## Generated descriptor and task

The only physical input is the new `fixture.make_descriptor` output for the
four declared seeds, two sizes and two quotes. All its fields are permitted:
`fixture_id,seed,n,quote,trips,duties,start_min,end_min,trip_energy,adjacency,
horizon_min,depot,stations,active_stations,prices,plugs,physics,expected_costs,
frame_schema,fleet_lower_bound_witness`. Mapping domains, adjacency tuple order,
numeric values and list order remain part of the bound descriptor. Physics
contains battery/reserve/SOC step/event block/default and station power/terminal
target/fleet cap. Expected costs are BUS100000, fee0 and premium1. No external
price table or geometry is substituted. All descriptors and aliases are bound
in paid preflight before outcomes; seed collisions cannot select replacements.

Each worker reads only its literal assigned folder under this directory's NEW
`attempt01`, after the launch gate. The twelve task fields are `task_id,phase,
base_seed,services,arm,quote,descriptor_sha256,a0_folder,a0_receipt_sha256,
a0_spec_sha256,a0_selected_sha256,a0_bank_sha256`. A supplied A0 folder must equal
the parent-constructed same-seed/size/arm A0 folder. Artifact contents never
choose another path. The complete48-stage order is determined by reviewed
`assigned_sequences`, published before dispatch, not by any result.

## Own-campaign records and metadata

Only that assigned worker's newly produced oracle outputs and its own A0
dependencies may be consumed. A0 dependencies are `spec.json`, `receipt.json`,
`best-records.json` and, for C1 only, `oracle/columns.jsonl`. They must match
the parent-held spec/receipt/selected/journal pins and source/task/descriptor
identity. No sibling output directories or closed experiment artifacts are
inputs. F1's bank is telemetry only, never a source for C1 or another sequence.

Whole buffers/lines are read and transiently JSON-decoded explicitly. A complete
produced route record is permitted for unchanged storage, full-record identity
comparison and passage to the original physical APIs. This is not claimed to
be identifier-only decoding. Scientific projections use ordered `trips`,
`route_nodes` or `route`, `charging_stops` and `expanded_grid_charging_stops`
(`stations,cst,cet,kwh`), stored original `cost,continuous_realized_cost`,
`terminal_energy_kwh,continuous_terminal_energy_kwh`, counted
`capacity_occupancy` triples and `continuous_realized_charging_blocks`.
Block fields are stop/block index, station, start/end minute, tariff hour/key,
price per kWh, grid kWh and realized kWh. Fresh original audit/realization/
validation drives loads, terminal values and physical admission. Cached fields
cannot substitute for this work. Original quote cost guards and fresh target
valuation are distinct; original records are never repaired or relabeled.

The returned original oracle summary is preserved whole as provenance. Its
declared operational/analysis fields are `charging_stage.status`, source
`columns_sha256`, cumulative `pricing_seconds`, plus original native status,
bound, stage timing, column/row counts and certificate-scope fields. Missing
fields remain unknown. Raw iteration/log files remain local; no extra trace
read, label reconstruction, physical-call counter or source query is authorized.
Native optimize counts for the original oracle remain unknown. C1's one local
binary call records its own supported native attributes and parameter readback.

Parent receipt reads preserve the full worker packet for accounting/provenance.
Admission depends on exact task/source/descriptor, completion/reap/return time,
strict versus physical/optimal/bank flags, fatal/config/resource/identity flags,
selected and bank pins, and finite resource/value fields. Compact readout uses
C/B/U costs/components, A0 target electricity, physical/raw witness counts when
complete, timings, unknowns and every planned state. Full-record preservation
does not manufacture missing dual vectors or reduced-cost labels.

## Read and resource bounds

Spec and compact dependency receipts are bounded by8MiB; selected records by
512MiB. Complete journals are streamed with512MiB total and16MiB per-line bounds.
No partial bank, invalid-column dropping, truncation or available-only rescue
is permitted. Each consumed buffer/stream is hashed once inside its paid stage;
another stage consuming the same dependency verifies its own declared input,
not a separate audit job. All interpretation, copying and publication are paid.
The source preparation/owner inventory separately binds the exact local sources
and registered sibling import closure; installed native dependencies are not
silently certified by Python source hashes.
