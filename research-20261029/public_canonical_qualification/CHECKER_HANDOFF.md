# Independent canonical checker handoff

Source only; no actual rich/descriptor/plan buffers, import, test, hash, native call or execution. No owner/control authored here.

API: `checker.independently_check(projected, claimed)`. Projection is the extractor author's agreed dictionary: selected variant, original descriptor, locations/arcs/stops, source_field_semantics, selected modeling_assumptions, source-bound od_transfer and expected_services. Numeric JSON float tokens must be retained as strings, not pre-rounded decimal replacements or live floats. The checker never calls producer/extractor and never repeats OD triangles.

Output includes status, independent_status, summary_matches, checks, denominators, complete predicate list and blocked_access_count. Claim comparison uses scientific status and the full denominator dictionary; diagnostic check IDs need not match the producer's. Every successful call audits n services, n pullout+n pullin predicates, n(n−1) direct+n(n−1) via-depot predicates, all emitted modes, all native/provenance legs and complete descriptor/policy mapping. Duplicate, extra or omitted modes cannot be a PASS. Malformed prerequisites return UNKNOWN, not a guessed completion. Runtime callers should distinguish a matching FAIL from a PASS.

The independent method first checks each existing movement's own incidence, timestamps, source OD fields, energy components and provenance; a separate service-pair walk then consumes expected incidences and checks exact canonical endpoints/roles/IDs and presence/absence. That differs from constructing the producer's expected-signature dictionary and comparing it wholesale.

Descriptor equality binds all native fields in addition to the recorded identity string. Expected service count is a bounded literal parameter (production37, prospective controls may be smaller); the worker must freeze it.

Original ordered binary64 formulas are recomputed only for per-field energy provenance, with an explicit binary64 host-profile gate and exact Fraction comparison of stored/recomputed binary values. Source OD tokens are separately compared as exact decimal rationals. This does NOT prove detour or waiting-energy dominance under rounded coefficients. Output leaves energy_path_dominance and continuous_wait_binary_bridge UNKNOWN, physical_extension UNATTEMPTED. Terminal opening0 and the source visit policies are bound explicitly; access for a different terminal-visit interpretation is not inferred.

Negative controls should alter both variant and matching descriptor where applicable, so coverage checks rather than mere identity checks catch the fault:

* Omit the forward feasible direct or via mode; add the reverse time-infeasible mode; duplicate an incidence under a fresh ID; add a third depot leg or wrong split.
* Move inbound/outbound times or charging-gap endpoints; alter terminal deadline/opening; alter any departure/full-inventory/depot-wait policy; classify a direct stationary wait at a source-flagged depot. No access failure becomes an ordinary off-depot wait.
* Corrupt service source seconds/native minutes, source ID/row binding, source OD distance/time/height or leg role; corrupt stored native/provenance energy together so only formula recomputation catches it.
* Alter charging acceptance/shared-grid/connector/resource fields, vehicle cap, market partition or cost mapping; preserve recorded case_identity to confirm it cannot override field mismatch.
* Forge claimed status or any denominator; omit source energy/components/provenance; send unsupported numeric types or excessive sizes. Require FAIL/UNKNOWN as appropriate, never a manufactured PASS.
