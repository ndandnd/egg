# One public metadata gate for a real scope limitation

The public37-service result is already resolved within its declared finite
movement graph. This new gate asks a distinct question: can direct-movement
canonicalization justify including arbitrary paths over the same declared
locations? It is not a rerun, a tighter solver tolerance, a new timetable or
a search for a more favorable support gap.

The independently reviewed conditional proof needs componentwise metric OD
data, canonical mode coverage, matching charging access and exact energy
consistency. An analytical terminal-access counterexample shows why geometry
alone is insufficient. The retained stripped descriptor cannot establish OD
properties. A previously archived PUBLIC rich input retains the full matrices.

This package tests only that first geometry gate, on one fixed public input,
before any later extension is considered. It reports every pair/triple in the
denominator and preserves all failures. Joint physical-path realizability of
the paired distance/time cells is UNKNOWN in this metadata. Consequently even
a metric PASS cannot extend the support certificate by itself. A FAIL rules
out this sufficient proof route without implying that additional paths remove
support failure. No automatic metric closure, route repair, new solve or retry.

Native calls0, no model fit, no source variant/service-row inspection, no
private/archive/sibling/sealed inputs. One complete JSON decode is permitted
only to project the named shared public fields; no embedded path is followed.
All actual bytes and source hashes are consumed once inside the separately
frozen metered worker. Source preparation remains unexecuted until that freeze.
