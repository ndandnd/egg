## Actual production trust boundary

`extractor.adopt` accepts decoded inputs and explicit fixed PINS solely as a pure parser/contract function. **Equality of PINS or True flags alone is not source authentication.** The new source-only worker reads each fixed committed buffer, compares its working bytes with its exact Git revision, hashes the consumed buffer once, decodes that same admitted buffer, and only then calls adopt. It seals the base and complete consumed manifest once immediately after extraction. Its callback requires both object identity and equality to those separately retained immutable seals, before and after search and final checking. The producer receives a separate deep copy with its own identity guard and the same immutable base seal. No serialized base record or subsequently edited same-identity object may bypass that admission.

The old complete audit supplies numerical validity of each source-bound leaf; the new extractor and checker rederive only branch identity/prefix coverage. New certificates are checked under those prefixes against the original semantic model. Every base leaf remains present, old infeasibility is retained, and failed new refinement falls back explicitly to its original lower. This is deliberate incremental proof composition, not acceptance of new arbitrary lowers by a verified=True flag.
