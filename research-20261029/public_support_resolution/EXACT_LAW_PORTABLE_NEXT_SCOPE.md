# Exact-law portable verification: next-scope feasibility

## Decision

A real portability gap exists: the closed standalone original-law checker does NOT certify the new exact-additive target. However, a receipt-adoption/summary-comparison export alone would not close that gap. **DEFER a new full numerical verification under a literal prohibition on repeating physical/tree/semantic predicates.** A distinct future portable-verification phase is worthwhile only if parent explicitly permits one fresh solver-free retained-evidence check for that new purpose. It must not resume either old attempt or rerun discovery, native planning, charging recovery, route selection or mixture optimization.

This assessment read only the handoff's relevant compact checkpoint and the named target/comparison RESULTS, INTERPRETATION, FINAL_RESOURCE and API/worker handoff records. No raw compressed evidence, old bundle, scientific source audit, imports, hashes, solver, replay, export or implementation was used. Historical advisory handoffs saying DRAFT are superseded by the closed receipts; they remain API documentation, not current launch authority.

## Two different deliverables must not be confused

1. A **portable receipt/summary consumer** could reproduce the direct/variance arithmetic from already admitted exact point summaries and a transferred lower receipt. It needs no new physical replay or tree check. That predicate has already been delivered by the successful comparison consumer. Repackaging it without a materially new interface test mostly duplicates paid work, and its result still TRUSTS the earlier admissions/lower. It is not independent end-to-end verification.
2. A **portable retained-proof verifier** would let a fresh user check the exact target sign from explicit model and witness/proof bytes, with no solver or repository installation. It necessarily evaluates physical feasibility of both retained NEW target candidates and validity/coverage of the target-row tree, then the mixture. Those are repeat mathematical checks for a distinct portability purpose, even if they do not rerun the original worker STAGES. Calling them “no replay” would be misleading. If no such checks are authorized, stop at the documented gap rather than export authoritative PASS flags.

Author-run command qualification would still not be external replication. Source/data redistribution rights remain unresolved; default output must remain a local review artifact, without an invented license or public release.
